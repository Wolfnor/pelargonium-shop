# Правила работы

## Названия задач

Формат: `[TYPE] Краткое действие`.

Допустимые типы: `RESEARCH`, `FEATURE`, `TASK`, `BUG`, `TEST`, `DOCS`.

Примеры:

- `[RESEARCH] Уточнить процесс приема заказа`
- `[FEATURE] Добавить карточку сорта`
- `[BUG] Исправить сохранение статуса заказа`

## Названия веток

Формат: `type/issue-number-short-name`.

- `feature/2-catalog-card`
- `fix/8-order-status`
- `docs/5-update-adr`
- `test/11-order-flow`

## Коммиты

Используется короткий формат Conventional Commits:

- `feat: add variety catalog card`
- `fix: save order status`
- `docs: update delivery model ADR`
- `test: add order form checks`

## Pull request

Название: `#номер Краткий результат`.

В описании указываются связанная задача, выполненные изменения, способ проверки и известные ограничения.

## Рабочий процесс доски

| Статус | Назначение | WIP-лимит |
| --- | --- | ---: |
| Backlog | Задачи, которые ещё не готовы к началу | без лимита |
| Ready | Задачи, соответствующие Definition of Ready | 6 |
| In Progress | Активная работа команды | 2 |
| Review | Проверка результата вторым участником | 1 |
| Test | Проверка критериев приёмки | 1 |
| Done | Полностью завершённые задачи | без лимита |

Команда не начинает новую задачу, если соответствующий WIP-лимит достигнут. Сначала участники помогают завершить уже начатую работу.

## Политики перехода

- Backlog → Ready: выполнены все условия Definition of Ready.
- Ready → In Progress: назначен владелец, работа начата, лимит не превышен.
- In Progress → Review: результат реализован и проверен автором.
- Review → Test: замечания ревью устранены.
- Test → Done: выполнены критерии приёмки и Definition of Done.
- Если задача заблокирована, причина фиксируется в комментарии, а карточка остаётся видимой на доске.

## Definition of Ready

Задачу можно брать в работу, если:

- понятны пользователь и ценность результата;
- записаны проверяемые критерии приёмки;
- определены приоритет, размер и владелец;
- выявлены зависимости;
- задача помещается в один недельный спринт;
- приложены необходимые данные, тексты или фотографии.

## Definition of Done

Задача считается завершённой, если:

- результат реализован;
- критерии приёмки проверены;
- выполнено ревью вторым участником;
- нет известных критических ошибок;
- документация и статус карточки обновлены;
- результат можно показать заказчику.

## Правило ежедневной синхронизации

На короткой встрече команда сначала рассматривает самую старую незавершённую карточку и блокировки. Каждый участник ведёт не более одной основной задачи одновременно.
